# DEVOS-052 — Implement Tool Gateway

**Dependencies:** DEVOS-051; DEVOS-043/044 (policy model/evaluator, Sprint 3). **Scope:** The Tool Gateway — "the central security rule: the existence of an API contract, workflow task, or agent instruction does not itself grant permission to perform an external action. Authority is evaluated at the server boundary" (`specs/api/poc-api-contracts.md` §56), following the exact chain: Typed Validation → Project Scope → Policy → Capability Permission → Credential Resolution → Provider Adapter (§56). Implemented in `packages/tools/src/gateway/` (`specs/architecture/repository-code-structure.md` §16: `gateway/`, `validation/`, `invocation/`). "Tool authority is evaluated independently of model output" (`poc-api-contracts.md` §32). Every invocation is recorded in `tool_invocations` (`specs/database/poc-database-schema.md` §14.2: `workflow_task_id`, `tool_capability_id`, `status`, `input_metadata`/`output_metadata` JSONB — sanitised, "raw secrets and sensitive provider payloads must not be persisted by default"). **Acceptance:** A tool invocation request (`{capability, target, parameters, idempotencyKey}`, `poc-api-contracts.md` §32 example) is validated against its capability's input schema, authorised via DEVOS-044's policy evaluator (closing that evaluator's "not yet wired into any real decision point" gap flagged in `DEVOS-SPRINT3-DECISIONS.md`), invoked, and recorded — an unauthorised or invalid request never reaches the provider adapter, and "tools must not bypass policy" (`specs/technical/poc-technical-implementation.md` §28).
