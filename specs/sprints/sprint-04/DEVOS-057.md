# DEVOS-057 — Implement Development Agent

**Dependencies:** DEVOS-056 (repository context); Sprint 2 agent runtime; Sprint 3 planning approval (DEVOS-047). **Scope:** Stage 7 — Development (`specs/workflows/software-change-workflow.md` §17, quoted in full): "Implement the approved plan through controlled repository actions." Inputs: "approved implementation package; repository context; development policies; tool permissions." Expected activities: "create a feature branch; inspect source code; modify source code; create/update tests; run permitted local validation; create commits; create a pull request where authorised." Authority: "The agent does not receive unrestricted repository access. Each external action must pass through the Tool Gateway and applicable policy." Output: "code change; commit evidence; pull request where applicable; implementation evidence." A new agent role/prompt (`packages/agents/src/prompts/developer/`, per `repository-code-structure.md` §42's named prompt folder), reusing the existing agent runtime (Sprint 2) and gated behind the planning approval (DEVOS-047) rather than a new gate. **Acceptance:** Consistent with Constitution Principle 6/7, the agent itself never directly writes to the repository or invokes git — it produces a structured, schema-validated proposed change (file paths + content), and the Tool Gateway's capabilities (DEVOS-052/054), not the model, actually apply it. No dedicated `development_agent` domain entity/table exists (there is none in the schema) — this is a normal `AgentDefinition`/`AgentVersion` with `role: 'DEVELOPMENT'`, matching every other planning-path agent's pattern (DEVOS-031–034).
