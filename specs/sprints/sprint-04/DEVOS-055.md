# DEVOS-055 — Implement Controlled Workspace

**Dependencies:** DEVOS-054 (Git adapter). **Scope:** An ephemeral, authorised development workspace (source description). This is the thinnest task in the sprint — the word "workspace" appears in the spec corpus exactly once, as a negative security constraint: "Development agent workspaces must not contain unrelated credentials" (`specs/architecture/repository-code-structure.md` §47, Secret Handling rule 5). No entity, database table, lifecycle state machine, or isolation mechanism (container, VM, temp directory, git worktree) is specified anywhere — every design choice in this task is an implementation-level assumption, not a spec derivation. **Assumption (flagged):** a workspace is a temporary local directory, scoped one-per-development-task, created via the Git adapter (DEVOS-054) cloning/checking out the target repository, and removed after the task's tool invocations complete — mirroring this codebase's existing `ArtifactStorage`/e2e-test temp-directory patterns (`mkdtemp`/`rm` in `tests/e2e/*.test.ts`) rather than a heavier container-based isolation mechanism, consistent with this sprint's own "prefer modular monolith patterns" risk guidance. **Acceptance:** A workspace is created scoped to a single development task, contains only the checked-out repository content (no injected credentials, no other task's data), and is reliably cleaned up whether the task succeeds or fails.
