# DEVOS-058 — Implement PR Creation Capability

**Dependencies:** DEVOS-052 (Tool Gateway), DEVOS-054 (Git adapter). **Scope:** "Create pull request through gateway" (source description) — the capability key `git.pull_request.create` is given as the literal worked example of a tool contract (`specs/api/poc-api-contracts.md` §32: `{"capability": "git.pull_request.create", "target": {"repositoryId", "baseBranch", "headBranch"}, "parameters": {"title", "bodyRef"}, "idempotencyKey"}`), risk-classified R3 ("Create/merge PR or external change" → "Review/approval", `software-change-workflow.md` §27). No concrete GitHub PR request/response schema, endpoint, or auth scope exists anywhere in the spec corpus. **User-authorized scoping decision (2026-08-22):** PR creation is implemented behind a swappable `PullRequestProvider` port and verified this sprint against a fake/local provider only — no real GitHub API call is made, per the same live-verification scoping decision as DEVOS-054. **Acceptance:** Given a branch with commits (from DEVOS-054/057), the capability creates a pull-request record (title, source/target branch, body reference) through the Tool Gateway's full validate→authorise→invoke→record chain, idempotent on its supplied key (a repeated request with the same idempotency key does not create a second PR) — verified against the fake/local provider; real GitHub API integration is explicitly flagged as future work.
