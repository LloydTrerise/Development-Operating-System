# DEVOS-054 — Implement Git Adapter

**Dependencies:** DEVOS-053 (credential abstraction). **Scope:** Repository read, branch, and commit operations (source description), within `packages/integrations/src/github/` per the exact adapter-internal structure `specs/architecture/repository-code-structure.md` §36 names (`github.adapter.ts`/`github.client.ts`/`github.mapper.ts`/`github.schemas.ts`). GitHub is the only provider named anywhere in the spec corpus, but **no concrete GitHub API contract, and no `repositories`/`branches`/`commits` table or domain entity, exists anywhere** — flagged explicitly. Git itself is provider-agnostic (a repository URL can be a real GitHub remote or a local path), so the adapter's core clone/branch/commit/diff mechanics are implemented against the real `git` CLI and are provider-independent; only PR creation (DEVOS-058) is GitHub-API-specific. **User-authorized scoping decision (2026-08-22):** this sprint's live verification uses a throwaway local git repository only — no real GitHub API calls are made, to avoid any risk to the user's real GitHub account. **Acceptance:** Given a repository path/URL, the adapter can clone/open it, create a branch, write file changes, and create a commit — verified against a real local git repository (not a mock of the `git` CLI); "provider SDKs must remain inside integration/adapter packages" (`repository-code-structure.md` §18) — no `git` CLI invocation exists outside this adapter.
