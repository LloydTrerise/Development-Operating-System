# DEVOS-056 — Implement Repository Context

**Dependencies:** DEVOS-055 (controlled workspace). **Scope:** File/search retrieval for the development agent (source description). Repository Context as a _category_ is well specified: "repository structure; source directories; configuration files; package definitions; dependency information; build configuration; test configuration; relevant source files... Repository Context is dynamic... An agent working on implementation should generally receive relevant repository information rather than an unbounded copy of the entire repository" (`specs/architecture/system-context-engineering-knowledge.md` §10); it "should normally be tied to a specific revision... where reproducibility requires it" (§28). The _retrieval mechanism_ itself is explicitly, deliberately deferred: "This document does not decide: ... repository indexing technology; file chunking strategy; retrieval algorithms" (§39). **Acceptance:** Given a workspace, a bounded file listing and file-content read (with a size limit, never an unbounded whole-repository dump) is available to the development agent, tied to the workspace's current checked-out revision; no vector search, embeddings, or indexing infrastructure is built (explicitly out of scope per §39) — a direct filesystem walk plus a simple substring/pattern search is the entire retrieval mechanism, flagged as an implementation choice.
