# Sprint 48 — Agent Principal & Attribution

**Source:** `specs/DEVOS-ACCESS-CONTROL-MODEL-BACKLOG.md` §5/§6.3 (candidate epic E29, Identity & Access Control Redesign).
**Conversion date:** 2026-09-24
**Status:** Converted and executed per explicit user authorization ("Proceed with sprint. Run through sprint fully without waiting for authorisation after each task. Stop once sprint is done", 2026-09-24), in direct response to a position report confirming Sprint 47 complete and Sprint 48 the recorded next item, per `AGENTS.md` §35/§4.2.

## Goal

Give every named agent a real `PRINCIPAL`/`AGENT_PROFILE` identity — one per `agents` row, shared across its own `agent_versions` history — with a real, resolved human `accountable_owner_id` where one can be found, and attribute real agent-run actions (context-manifest and artifact-creation audit records) to that agent's own principal id instead of the generic `devos-agent-runtime` system actor. Per the epic's own resolved decision §9.7, agents never authenticate: no credential, no login, no bearer token is added anywhere in this sprint.

## Grounding (confirmed by direct code inspection and live Postgres verification at implementation time)

- `agents` (migration `0015`) has no `created_by` column of its own — only `agent_versions.created_by` does (a real, disclosed, pre-existing asymmetry from DEVOS-025, since no spec documents either). `accountable_owner_id` (DEVOS-296) therefore resolves from each agent's own earliest (`version` 1) `agent_versions.created_by`, the only creator-attribution field that exists for an agent anywhere in this schema.
- Every real path that creates an `agents` row (`createAgent`, `installAgentVersion`, and the project-type-template clone pipeline in `create-project.ts`) funnels through exactly two low-level repository functions — `createAgentDraftCreator` (`packages/database/src/repositories/create-agent-draft.ts`) and `createProjectWithClonesCreator` (`packages/database/src/repositories/create-project-with-clones.ts`) — both of which already call `createAgentRepository(trx).create(agent)` directly and already have the new `Agent` and its first `AgentVersion.createdBy` in hand. These are the real chokepoints DEVOS-295/296 hook into, the same "one true chokepoint" reasoning Sprint 46's DEVOS-286 already applied to `createMembershipRepository.create()` — no repository interface needed widening, so all 19 existing `AgentRepository` test fakes stay valid unchanged.
- `runAgentTask` (`packages/application/src/tasks/run-agent-task.ts`) is the one real chokepoint every one of the six concrete agent-task handlers (discovery/requirements/technical-design/planning/development/review) already shares — it already resolves the real `Agent`/`AgentVersion` being executed, and already calls `deps.recordContextManifest(manifest)` for every single agent execution, writing a real `context_manifest.created` audit record that — before this sprint — was always attributed to the generic `devos-agent-runtime` system actor regardless of which specific agent ran.
- `AuditActorType` (`packages/domain/src/audit/audit-record.ts`) was a 2-value `'USER' | 'SYSTEM'` enum with no way to represent "a specific agent, not a human, not the undifferentiated system actor" — real agent attribution needed a real third value, not a reused sentinel.
- This environment has 26,594 real `agents` rows (and as many `agent_versions` rows) at the time migration `0050` was written — a per-row JS loop (the pattern migration `0048` used for organisations, at a much smaller real scale) would not finish in reasonable time here, so the backfill is set-based SQL. A live query confirmed **every one** of the 26,594 real `agent_versions.created_by` values already resolves to a real, already-backfilled `HUMAN` principal (Sprint 46's own DEVOS-284 backfill) — zero unresolvable owners in this environment, though the migration's own resolution logic still leaves `accountable_owner_id` `NULL`, not fabricated, for any environment where one doesn't resolve.

## Real bugs found and fixed during implementation (not just disclosed)

1. **`agent_profiles`'s hard FK broke existing e2e test cleanup.** Several real e2e pilot tests (`knowledge-platform-lifecycle-pilot.test.ts`, `knowledge-platform-marketplace-pilot.test.ts`, `approval-reliability-reduction-pilot.test.ts`) hard-delete the real test `agents` rows they create as part of their own cleanup — a real, disclosed regression surfaced by this sprint's own required full `tests/e2e` run: `DELETE FROM agents ...` now violated `agent_profiles_agent_id_fkey`. Fixed by adding `ON DELETE CASCADE` to that FK in migration `0050` (a profile has no independent existence once its own agent is gone — the correct semantics here, not a workaround) and applying the equivalent `ALTER TABLE` against the already-migrated real database to keep it in sync with the corrected migration file.
2. **`seed.ts`'s ownerless-agent gap.** Mirroring Sprint 46/47's own identical class of finding: `packages/database/src/seed.ts` inserts its six seeded agents' `agents`/`agent_versions` rows directly via raw SQL, bypassing `createAgentDraftCreator`'s real, ongoing get-or-create — a genuinely fresh `migrate`+`seed` database would leave all six seeded agents without a `PRINCIPAL`/`AGENT_PROFILE` row. Fixed by seeding real `principals`/`agent_profiles` rows for all six directly in `seed.ts`, `accountable_owner_id` resolving to `SEED_PRINCIPAL_ID` (every seeded `agent_versions.created_by` already uses it).
3. **A real, non-deterministic e2e-suite flake, traced to this session's own leftover stray processes, not a code defect.** The full `tests/e2e` suite's first post-fix run showed 7 failures across `build-test-review.test.ts`, `engineering-intelligence-pilot.test.ts`, and `hardening.test.ts` (5 of its own 9 tests) — investigated per `AGENTS.md` §17 rather than dismissed. A `git stash`-isolated re-run of `build-test-review.test.ts`'s rework path against the unmodified pre-Sprint-48 baseline still passed, and a repeated isolated re-run against this sprint's own code sometimes passed and sometimes failed — real evidence this was never a deterministic logic bug. Root-caused to two `node.exe` processes, left running since this sprint's own earlier manual live-verification pilot (DEVOS-297's own real end-to-end proof, run directly against `apps/api`/`apps/worker` with `AGENT_MODEL_ADAPTER=fixture`), that the session's own prior stray-process check had failed to detect — its command-line filter matched literal `apps.(api|worker)` substrings, but the pilot's own processes had been launched with `cd apps/api && node ... dist/main.js`, whose actual OS-reported command line never contains that substring, a genuine blind spot in the check itself. That stray, still-running fixture-adapter worker (configured with `AGENT_MODEL_ADAPTER=fixture` but no `REVIEW_FIXTURE_SEQUENCE`, so it always returns the single default `review-v1`/`PASS` fixture) was racing the e2e suite's own freshly spawned, correctly-configured worker for the exact same real Postgres task queue — whichever claimed a given `AGENT_TASK` first determined its outcome, exactly the class of contention Sprint 19/41/43/45/46/47 already disclosed, just self-inflicted this time rather than left over from a genuinely prior session. Killed by PID (`Get-CimInstance Win32_Process` without the flawed command-line filter); the full suite then ran clean twice.

## In scope

- **DEVOS-295** — `agent_profiles` table (migration `0050`), one row per existing `agents` row, `agent_id`/`principal_id` always the same string (decision §9.4); `packages/domain/src/agents/agent-profile.ts` defines `AgentProfile`/`AgentProfileRepository`; `packages/database/src/repositories/agent-profiles.ts` implements it plus the real, ongoing `ensureAgentPrincipal()` chokepoint wired into `create-agent-draft.ts`/`create-project-with-clones.ts`.
- **DEVOS-296** — `accountable_owner_id`, resolved from each agent's own earliest `agent_versions.created_by` where it names an already-backfilled `HUMAN` principal; left absent, not fabricated, otherwise.
- **DEVOS-297** — `AuditActorType` widened to `'USER' | 'SYSTEM' | 'AGENT'`; `runAgentTask`'s return value gains `agentId`; `recordContextManifest`'s type gains a required `actorId` parameter (TypeScript's fewer-parameters leniency keeps every existing test fake type-checking unmodified) and its real implementation now writes `actorType: 'AGENT'`/`actorId` for every real agent execution; the six concrete agent-task handlers' own published-artifact `createdBy` fields use the resolved `agentId` instead of the generic system actor; `publish-artifact.ts` resolves `'AGENT'` vs `'USER'`/`'SYSTEM'` via a real `principals` lookup. `invokeTool`'s own principal id (Tool Gateway authorization + its own audit trail) and the automatic rework-run trigger in `runReviewAgentTask` deliberately stay attributed to the generic system actor — a disclosed scope boundary, not an oversight (see `DEVOS-297.md`).
- **DEVOS-298** — Validation, documentation, and gap disclosure, including this sprint's own required real end-to-end proof.
