## Real bugs found and fixed during this sprint's own validation, not merely disclosed

1. **`agent_profiles`'s hard FK broke real e2e test cleanup — a genuine regression, fixed.** The first full `tests/e2e` run (immediately after DEVOS-295–297's implementation) showed 8 files / 9 tests failing, three of them a clean, unambiguous root cause: `knowledge-platform-lifecycle-pilot.test.ts`, `knowledge-platform-marketplace-pilot.test.ts`, and `approval-reliability-reduction-pilot.test.ts` each hard-delete the real test `agents` rows they create as part of their own cleanup, and migration `0050`'s new `agent_profiles.agent_id` FK (no `ON DELETE CASCADE` in its first draft) rejected that with a real foreign-key violation. Fixed by adding `ON DELETE CASCADE` to the FK in the migration file and applying the equivalent `ALTER TABLE agent_profiles DROP CONSTRAINT ... ADD CONSTRAINT ... ON DELETE CASCADE` directly against the already-migrated real database, keeping the live schema and the migration source in sync (a profile has no independent existence once its own agent is gone — correct semantics, not a workaround). Re-running the full suite after this fix alone brought the failure count down to 7 files / 7 tests.
2. **A real, non-deterministic e2e-suite flake, root-caused to this session's own leftover stray processes, not a code defect.** The remaining failures (`build-test-review.test.ts`'s rework-path scenario, `engineering-intelligence-pilot.test.ts`'s bottleneck-ranking assertion, and 5 of `hardening.test.ts`'s own 9 tests) were investigated per `AGENTS.md` §17 rather than dismissed:
   - A `git stash`-isolated re-run of `build-test-review.test.ts`'s rework-path scenario against the unmodified pre-Sprint-48 baseline (`839d972`) passed cleanly — ruling out a pre-existing bug this sprint merely surfaced.
   - A repeated isolated re-run of the same scenario against this sprint's own code, unchanged, **sometimes passed and sometimes failed** — real, direct evidence this was never a deterministic logic bug in this sprint's own implementation.
   - A live process inventory (`Get-CimInstance Win32_Process -Filter "Name = 'node.exe'"`) found two `node.exe` processes still running, both real `apps/api`/`apps/worker` instances left over from this sprint's own earlier manual live-verification pilot (DEVOS-297's own real end-to-end proof, described below) — started with `AGENT_MODEL_ADAPTER=fixture` but no `REVIEW_FIXTURE_SEQUENCE`, so that stray worker always returns the single default `review-v1`/`PASS` fixture. This session's own earlier stray-process check (before starting that pilot's servers, and again before the first `tests/e2e` run) had used a command-line filter matching the literal substring `apps.(api|worker)` — a genuine blind spot, since the pilot's own processes were launched via `cd apps/api && node ... dist/main.js`, whose real OS-reported command line never contains that substring. That stray worker was racing every subsequent e2e test's own freshly spawned, correctly-configured worker for claims on the exact same real Postgres task queue — whichever process claimed a given `AGENT_TASK` first determined its outcome, exactly the class of environment contention Sprint 19/41/43/45/46/47 already disclosed, just self-inflicted this session rather than left over from a genuinely prior one. Killed both stray processes by PID; the full suite then ran clean, twice in a row (27/27 files, 52/52 tests both times).

## Real, disclosed gaps — deliberate, not oversights

- **`invokeTool`'s own principal id stays the generic system actor**, in every one of `run-development-agent-task.ts`'s three tool invocations — switching it to the development agent's own principal id would require granting every individual agent principal its own real project membership, a genuine access-grant expansion this sprint's own attribution-only scope doesn't authorize. Disclosed in `DEVOS-297.md` as a real, deliberate boundary, not an oversight.
- **The automatic rework-run trigger in `runReviewAgentTask`** stays attributed to the generic system actor — starting a new run is a platform orchestration decision, not the review agent's own produced output (which is itself correctly agent-attributed).
- **No UI surfaces an agent's `accountable_owner_id` anywhere** — this sprint's own backlog scope (§6.3) names no UI story for it, unlike Sprint 47's DEVOS-293; a candidate for a future sprint.
- **`agent_profiles`'s own `agent_id`/`principal_id` redundancy** (always the same string, by decision §9.4) is a deliberate, disclosed design choice — `agent_id` carries the real `uuid` FK to `agents.id` for referential correctness (with cascade), `principal_id` carries the real `text` FK to `principals.id` matching that table's own native column type; storing both avoids a cross-type FK Postgres cannot express directly.
- **No new agent authentication surface of any kind was added** — confirmed by design (no `AGENT_CREDENTIAL` table, no bearer-token path, no login mechanism anywhere in this sprint's diff) and by this task's own real end-to-end proof, which drove every real agent action exclusively through the existing internal workflow/task-handler execution path.
