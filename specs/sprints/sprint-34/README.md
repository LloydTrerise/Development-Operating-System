# Sprint 34 — Remaining Pages: Restyle + Detail Views

**Source:** `specs/DEVOS-UI-UX-REDESIGN-BACKLOG.md` §6.6 (E28 UI/UX Redesign & Full Functional Coverage, sixth sprint).
**Conversion date:** 2026-09-22
**Status:** Converted per explicit user authorization ("start sprint 34. Run through this sprint without waiting on authority", 2026-09-22). Depends on Sprint 29's theme/nav/`features/`/routing foundation (COMPLETE). No dependency on Sprints 30–33, though it reuses Sprint 31/33's own established `Paper`/`PanelHeader` restyle convention and the `/{area}/:id` `DetailPageLayout` routing convention.

## Goal

Restyle the six remaining un-restyled pages (Organisations, Project Types, Agents, Knowledge Sources, Cost, Engineering Intelligence) to the established Nocturne visual language, and close the two real, disclosed detail-view gaps the backlog names: a real Agent detail view (`GET /agents/:id`) and a real Knowledge Source detail view (`GET /knowledge-sources/:id`).

## Grounding (confirmed by direct code inspection before scoping)

- **`GET /agents/:agentId` already exists and is already wired** — `apps/api/src/routes/agents.ts:53-61` calls the existing, unmodified `getAgentForPrincipal` use case. The real gap is zero client wrapper (`api-client.ts` has `listAgents`/`listAgentVersions`/`getAgentQuality`/mutation wrappers, but no single-agent fetch) and zero detail route/page — `AgentsPage.tsx` renders every agent's full version history inline on one page, with no per-agent navigation anywhere. DEVOS-230 is scoped as client-wrapper + UI work, not a new backend route, matching the same pattern Sprints 31/33 already established for their own named "gaps."
- **`GET /knowledge-sources/:knowledgeSourceId` already exists and is already wired** — `apps/api/src/routes/knowledge-sources.ts:57-69` calls the existing, unmodified `getKnowledgeSourceForPrincipal` use case. Same real gap shape: no single-source client wrapper, no detail route — `KnowledgeSourcesPage.tsx` does all editing inline in table rows. DEVOS-231 is scoped identically to DEVOS-230.
- **Neither `Organisation` nor `ProjectType` has a mockup screen** — confirmed via a case-insensitive grep of `Design/DevOS.dc.html` for `organisation`/`project-type`/`agents`/`knowledge`: the mockup's own `navGroups` (line 850) names `Agents`/`Knowledge`/`Artifacts` as unwired (`id: null`) Platform placeholders, and does not name Organisations or Project Types at all. Per the backlog's own DEVOS-229 acceptance text ("no mockup screen exists so layout follows the design system's general rules"), both pages are restyled to this epic's own already-established `Paper`/`PanelHeader` bordered-panel convention (first used by `GovernancePage.tsx`'s DEVOS-219, then `WorkflowLibraryPage.tsx`'s DEVOS-223 and `ProjectDetailPage.tsx`'s DEVOS-225/226/227), not to a named mockup layout.
- **`Agent` (`packages/contracts/src/agents.ts:20-27` `AgentConfiguration`) has no "knowledge access" or "policies" field anywhere in the domain model** — confirmed by direct inspection of `AgentConfiguration` (`role`/`provider`/`modelRef`/`inputSchemaRef?`/`outputSchemaRef?`/`allowedCapabilities: string[]`) and `Agent`/`AgentVersion` themselves. `ui-spec.txt` §15 (Agent Catalogue) lists "Knowledge access: Permitted sources" and "Policies: Authority constraints" as fields, but no real data source for either exists in this codebase — no agent-to-knowledge-source binding, no per-agent policy record. The real Agent detail view surfaces every field that *does* have a real source (name, key, description, agent-level status, per-version status/role/provider/model/`allowedCapabilities`, review pass rate) and discloses the other two as not backed by real data, rather than fabricating them — the same "omit rather than invent" discipline `HomePage.tsx`'s System Health tile and `ProjectsPage.tsx`'s health line already established.
- **`KnowledgeSource` (`packages/domain/src/knowledge/knowledge-source.ts`) has no dedicated "permissions" or "freshness" field** — confirmed by direct inspection: the closest real signals are `sharedAcrossOrganisation` (an organisation-visibility flag, the only real access-scope signal that exists) and `updatedAt` (a real last-modified timestamp, the only real recency signal — there is no separate ingestion/sync-freshness concept anywhere in this codebase). `ui-spec.txt` §17 (Knowledge UI, "Source detail: Status, permissions, freshness") is satisfied honestly using these two real fields plus `status`, not by fabricating a permissions matrix or a sync-freshness score.
- **`getKnowledgeSourceReferences` already exists and is already used by the list page** (DEVOS-184) — the detail view reuses it unchanged for the same source's own usage-traceability list, rather than duplicating the fetch differently.
- **`CostPage.tsx`/`EngineeringIntelligencePage.tsx` already use `Paper variant="outlined"` sections**, unlike every other un-restyled page — their own DEVOS-152/156/165/171 acceptance text already called for exactly this shape. DEVOS-232 is a lighter restyle than the other four stories: adding this epic's own `PanelHeader` title-bar convention (a bordered header row inside each `Paper`, replacing the current plain `Typography variant="h6"` above each `Paper`) without changing any data-fetching, breakdown-dimension, or DORA/bottleneck logic.
- **No new shared component is extracted for `PanelHeader`** — it is already duplicated verbatim across `GovernancePage.tsx`, `WorkflowLibraryPage.tsx`, and `ProjectDetailPage.tsx` (three independent local copies, confirmed by direct inspection), an established repo convention of a small per-file local component rather than a shared one. This sprint's six restyled pages each define their own local copy identically, consistent with that precedent, rather than introducing a new shared component and retrofitting three unrelated, already-complete files outside this sprint's own scope.

## In scope

- **DEVOS-229** — Organisations + Project Types restyle: `Paper`/`PanelHeader` bordered-panel convention on both pages' existing list/create/edit logic, unchanged. `OrganisationsPage.tsx`'s existing inline expand-in-place settings row (DEVOS-227) and `ProjectTypesPage.tsx`'s existing `ProjectTypeWorkflowsEditor`/`ProjectTypeAgentsEditor` child panels are restyled at the outer-wrapper level only, not altered internally.
- **DEVOS-230** — Agents restyle + a real Agent detail view: a new `getAgent` client wrapper against the existing, unmodified `GET /agents/:agentId` route; `AgentsPage.tsx` restyled into a summary table (key, name, status, latest version, latest version status, review pass rate) with row-click navigation to a new `/agents/:id`; a new `AgentDetailPage.tsx` (identity, per-version table with the existing Publish/Draft-new-version actions moved here, capabilities, and a disclosed knowledge-access/policies omission).
- **DEVOS-231** — Knowledge Sources restyle + a real detail view: a new `getKnowledgeSource` client wrapper against the existing, unmodified `GET /knowledge-sources/:knowledgeSourceId` route; `KnowledgeSourcesPage.tsx` restyled into a summary table (key, name, type, status, shared badge, used-by count) with row-click navigation to a new `/knowledge/:id`; a new `KnowledgeSourceDetailPage.tsx` (identity/status/shared/freshness, content edit form, usage/reference list, share/archive actions — all moved here from the list page's inline row actions).
- **DEVOS-232** — Cost + Engineering Intelligence restyle: `PanelHeader` title-bar convention added to each page's existing `Paper` sections; zero change to data-fetching, breakdown-dimension, or DORA/bottleneck logic.
- **DEVOS-233** — Validation, documentation, and gap disclosure.

## Out of scope

Any new backend route, use case, or domain field. A real "knowledge access" or "policies" concept for agents (no data source exists). A real permissions/freshness model for knowledge sources beyond `sharedAcrossOrganisation`/`updatedAt` (no data source exists). A `/organisations/:id` detail route (no acceptance text in DEVOS-229 requires one — `PATCH /organisations/:id` was already closed by Sprint 33's inline affordance). Any change to `ProjectTypeWorkflowsEditor.tsx`/`ProjectTypeAgentsEditor.tsx` internals, `publishAgentVersion`/`createNewAgentVersion` semantics, or `shareKnowledgeSource`/`archiveKnowledgeSource`/`updateKnowledgeSource` semantics. Extracting a shared `PanelHeader` component.
