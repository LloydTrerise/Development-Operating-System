# DEVOS-308 — `AUDIT_LOG` reconciliation

**Priority:** P2
**Acceptance summary (from backlog §6.6):** Written confirmation that `audit_records` (§2.7) satisfies the source document's `AUDIT_LOG` table as-is, or the specific, narrow delta if one is found — not a new table by default.

## Method

The source document's `AUDIT_LOG` entity (its "Access roles, work items and audit" entity-relationship diagram, plus its entity-reference table) was extracted from `Analysis/DEVOS Access Control Model.docx` and compared column-for-column against `audit_records`' real, live schema (`packages/database/migrations/0012_audit_records.ts`) and its domain type (`packages/domain/src/audit/audit-record.ts`).

## Source document's `AUDIT_LOG`

```
AUDIT_LOG {
    uuid id PK
    uuid actor_principal_id FK
    string correlation_id
    string action
    string entity_type
    uuid entity_id
    json before_after
    datetime occurred_at
}
```

Purpose: "Append-only record of every change." Key constraint: "`correlation_id` ties an agent run to what triggered it."

## Column-by-column reconciliation

| `AUDIT_LOG` column      | `audit_records` equivalent                                       | Verdict                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id` uuid PK            | `id` uuid PK                                                     | Exact match.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `actor_principal_id` FK | `actor_type` (`'USER' \| 'SYSTEM' \| 'AGENT'`) + `actor_id` text | **Narrow delta.** `audit_records` needs to distinguish a genuine principal actor (`USER`/`AGENT`) from the undifferentiated platform system actor (`SYSTEM`, e.g. `devos-agent-runtime`'s own orchestration writes) — a real distinction the source document's own single `actor_principal_id` FK cannot express, so the two-column shape is not accidental. For `USER`/`AGENT` rows, `actor_id` holds a real `principals.id` value as of this epic (Sprint 46 backfilled every human; Sprint 48's DEVOS-297 confirmed every agent-run action is attributed to its own agent principal) — semantically equivalent to the source document's FK. It is not, however, a database-enforced FK to `principals.id` (`actor_id` is a plain `text` column) — unlike `target_id`, which _is_ a genuine `uuid`. This is a real, narrow, disclosed gap: nothing stops a future write from putting a non-existent id in `actor_id`, though no code path does so today. |
| `correlation_id`        | `correlation_id` (indexed)                                       | Exact match — already present and indexed since `0012`, confirmed by `audit_records_correlation_id_idx`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `action`                | `action`                                                         | Exact match.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `entity_type`           | `target_type`                                                    | Exact match, renamed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `entity_id` uuid        | `target_id` uuid                                                 | Exact match, renamed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `before_after` json     | `metadata` jsonb                                                 | **Narrow delta.** `metadata` is a free-form jsonb bag, not a structured `{before, after}` pair — every existing writer already uses it for whatever shape suits the action (`{ changes }`, `{ previousRole, role }`, `{ principalId, jobRoleId }`, …), a convention established since `0012` itself and used consistently by all ~30 `auditRecords.create()` call sites across the epic's own new use cases (Sprints 46–51). Functionally equivalent for audit/forensic purposes — every field needed to reconstruct what changed is present — but not a literal before/after diff structure.                                                                                                                                                                                                                                                                                                                                                              |
| `occurred_at`           | `created_at`                                                     | Exact match, renamed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

**Additive, not a gap:** `audit_records` also carries `organisation_id` (required) and `project_id` (optional) — necessary for this codebase's real multi-tenant scoping, which the source document's own single-tenant-per-install `AUDIT_LOG` sketch does not need to express — and `outcome` (`SUCCESS`/`FAILURE`), letting a denied/failed action be audited too, which the source document does not name at all.

## Conclusion

**No new `AUDIT_LOG` table is needed.** `audit_records` satisfies the source document's table as-is for every column that matters for its stated purpose ("append-only record of every change," "`correlation_id` ties an agent run to what triggered it") — both already fully real and exercised. Two narrow, disclosed deltas exist (`actor_id` is an unconstrained `text` column rather than a real FK; `metadata` is free-form rather than a structured before/after pair) — neither blocks any of this epic's own stories, and fixing either is a schema-tightening exercise with no story in this epic naming it, so it is disclosed here rather than undertaken.

## Acceptance

Confirmed by direct schema/type inspection, not assumed. No code change required for this task.
