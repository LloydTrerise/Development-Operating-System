# DEVOS-068 — Implement Retry/Rework Limits

**Dependencies:** DEVOS-067 (rework transitions). **Scope:** "Bounded loops and escalation" (source description). **No numeric bound is specified anywhere in the spec corpus** — Workflow Principle 7 ("Rework returns to the smallest appropriate prior stage," §8) and the Key Risk "Reliability — test restart, duplicate delivery, and idempotency before adding autonomy" (§11) establish that rework must be bounded in spirit, but no task file, ADR, or NFR states a number. **Assumption (flagged):** a small, explicit, configured limit on consecutive automatic rework cycles per work item (not per run, since DEVOS-067 creates a new run each cycle) — once reached, no further automatic rework run is created; the work item is left in a state that makes clear human escalation is required, rather than looping indefinitely. **Acceptance:** after the configured number of consecutive `CHANGES_REQUIRED` review outcomes for the same work item, no further automatic rework run is created, and the escalation state is visible via the API — verified against a real repeated-failure scenario, not just a unit-level counter check.
