# DEVOS-062 — Implement Build Adapter

**Dependencies:** DEVOS-052 (Tool Gateway), DEVOS-054 (Git adapter — same real-CLI-execution precedent), DEVOS-055 (workspace). **Scope:** "Run and record builds" (source description). Stage 8 — Automated Validation (`specs/workflows/software-change-workflow.md` §18) lists "build" as one of several validation activities, and requires the workflow to record "commands executed; results; failures; warnings; environment; relevant revision; timestamp." `specs/architecture/repository-code-structure.md` §45 names `build-run.ts` as a tool capability file alongside the existing four (`repo-read`/`repo-write`/`git-commit`/`pull-request-create`) — no input/output schema is specified for it anywhere. **Assumption (flagged):** a new `build-run` capability, invoked through the existing Tool Gateway exactly like Sprint 4's capabilities (no new engine mechanism), executes a real, configured shell command via a real child process against the task's real workspace (mirroring DEVOS-054's real-`git`-CLI precedent rather than a simulated/mocked build) and captures its exit code, stdout, and stderr as the invocation's recorded output. The command itself is not hardcoded to any particular build tool — it comes from configuration (mirroring how the `Git` integration's `repositoryPath` is configuration, not a hardcoded value), since no spec names one. **Acceptance:** invoking `build-run` against a real workspace with a real configured command runs it for real and returns its exit code/stdout/stderr as tool output, authorised/audited/idempotent exactly like every other Tool Gateway capability (DEVOS-059).
