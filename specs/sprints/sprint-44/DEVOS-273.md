# DEVOS-273 — Re-run the full route-to-UI audit

**Priority:** P0
**Acceptance summary (from backlog §6.17):** Every backend route across the whole application (the original 91 plus every route added by Sprints 35–43) is re-verified; every "N"/"P" verdict this document committed to closing now shows "C" (or an explicitly disclosed, deliberate exception).

## Method

Every route was extracted programmatically from `apps/api/src/routes/*.ts` by matching each route object's `method:`/`pattern:` pair (24 files, 105 routes — up from the v3.0 audit's 91, the growth entirely accounted for by Sprints 39–43's new route files: `notifications.ts`, `search.ts`, `system-health.ts`, `tool-capabilities.ts`, `workflow-library.ts`, plus 4 new membership routes on `organisations.ts` and one new `GET /runs/:runId` on `workflow-runs.ts`).

Every `export function` in `apps/web/src/api-client.ts` was mapped to the `/api/v1/...` URL template it requests. The two lists were diffed by path shape (`:param`/`${var}` normalized to a common token) to find routes with **zero client wrapper**. Every wrapper that *does* exist was then independently checked for at least one real call site anywhere else in `apps/web/src` — not just that the wrapper compiles — to catch the exact failure mode Sprint 38 found and fixed for `listSharedKnowledgeSources`/`installKnowledgeSource` (a real wrapper, zero real caller) before assuming "has a wrapper" means "reachable."

## Actual results

**96 of 105 routes (91%) are genuinely reachable through the UI — verdict `C`.** By area, matching and re-confirming every "Covered" and "Confirmed gap" line from `specs/DEVOS-UI-UX-REDESIGN-BACKLOG.md` §2.3 plus every net-new area from §2.4:

- Organisations (list/create/rename/org-level membership), Projects (list/create/rename/membership/tool-capability toggle), Project Types (full CRUD + workflow/agent template editors), Work Items (list/create/update/detail), Workflows (draft/validate-client-side/version/diff/publish/runs/start-from-version), Workflow Library (org-wide aggregate view), Workflow Runs (start/poll/detail/task drill-down/agent-execution + tool-invocation summaries), Agents (list/create/publish/versions/quality/detail/marketplace share+install), Knowledge Sources (list/create/update/archive/references/detail/marketplace share+install), Policies (CRUD/publish/simulate), Approvals (list/approve/reject/run-scoped visibility), Audit (project+org), Cost (project+org), Engineering Intelligence (project+org+slowest-workflows), Release Readiness, Health, Artifacts (library/viewer/version-history/diff/provenance), Integrations (list/register), Tool Capabilities (list/toggle), System Health (Home KPI tile), Search (global top-bar + Command Palette), Notifications (bell/list/mark-read) — all `C`.

**9 of 105 routes are not wrapped-and-called.** Each is individually accounted for below; none represents a real, previously-committed gap left open.

## Secondary finding, re-confirmed not fixed

`ApprovalsPage.tsx`'s unbounded per-approval evidence-fetch loop (`getArtifactVersionById`, once per evidence artifact-version id across every approval on the page) — first disclosed Sprint 35, re-confirmed worsening Sprint 43 (approval count keeps growing) — is still present, confirmed by direct inspection of the same unchanged `useEffect` this sprint. No story in `specs/DEVOS-UI-UX-REDESIGN-BACKLOG.md` §6.17 names this bug, so per AGENTS.md §8 ("avoid unrelated cleanup ... narrowly scoped implementation step") it is not fixed here. It has now been disclosed, unfixed, across four consecutive sprints (35, 39's adjacent verification, 43, 44) with no owner decision — recorded plainly rather than silently repeated a fifth time, so the user can decide whether it warrants its own follow-up.
