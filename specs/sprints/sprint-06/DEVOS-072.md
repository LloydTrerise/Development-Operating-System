# DEVOS-072 — Implement Release Policy Model

**Dependencies:** DEVOS-043/044 (policy entity + evaluator), DEVOS-069 (release readiness). **Scope:** "Environment-specific release authority" (source description) — grounds Stage 11 — Release (§22): "The workflow must verify: target environment; applicable policy; ..." No release/deployment-specific rule shape or schema is specified anywhere in the spec corpus. Rather than a new domain entity, this extends the existing, already-generic `Policy`/`evaluatePolicies` mechanism (DEVOS-043/044, later extended for conflict detection by DEVOS-048) with an environment dimension, so a published policy can express "staging: ALLOW, production: DENY" (or `REQUIRE_APPROVAL`) for a release-shaped action — reusing exactly the precedent DEVOS-048 already set for extending this evaluator's condition matching, not introducing a parallel authorization model. **Acceptance:** given a published release policy with environment-conditioned rules and a requested target environment, the evaluator deterministically returns the correct decision (`ALLOW`/`DENY`/`REQUIRE_APPROVAL`); an environment with no matching rule falls through to the policy's own default effect and then the evaluator's global fallback, exactly like every other policy dimension already does.
