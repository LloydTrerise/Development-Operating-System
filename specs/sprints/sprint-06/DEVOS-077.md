# DEVOS-077 — Implement Release Failure Handling

**Dependencies:** DEVOS-074 (deployment adapter), DEVOS-075 (post-release validation), DEVOS-076 (release evidence). **Scope:** "Retry, stop and authorised rollback path" (source description) — §24 Retry Rules ("Retry only transient failures automatically"; "Do not automatically retry permission denials"; "Bound agent retries"; "Escalate after the configured retry threshold") and §25 Human Intervention (`Retry`/`Rework`/`Cancel` actions). No numeric retry/rollback bound is specified anywhere — mirrors the exact gap DEVOS-068 already resolved for rework, with an explicit flagged assumption expected here too. A failed deployment or failing post-release validation must not silently retry indefinitely nor silently roll back — rollback is itself a controlled external action requiring the same authorisation discipline as the original release (§27 Risk Model, R3/R4), not an automatic recovery. **Acceptance:** a transient deployment failure is retried up to a bounded, explicit limit before escalating; a failing post-release validation stops the release from being considered successful and does not automatically roll back; an authorised rollback path exists and itself produces evidence/audit records exactly like the original deployment did; every attempt (success or failure) is recorded, and no path loops indefinitely.
