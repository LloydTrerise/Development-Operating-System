# DEVOS-075 — Implement Post-Release Validation

**Dependencies:** DEVOS-064 (validation-task precedent), DEVOS-074 (deployment adapter). **Scope:** "Smoke/health validation" (source description) — Stage 11 — Release (§22) implies verification of the release result before it is considered complete; no concrete smoke/health-check mechanism or contract is specified anywhere. Mirrors DEVOS-064's `runValidationTask` precedent exactly: no agent involved, deterministic platform code calling the Tool Gateway directly against the real local staging target DEVOS-074 just deployed to, recording a real pass/fail result rather than an agent's claim (Workflow Principle 12, §8). Whether this reuses a generalized capability or introduces a narrowly-scoped new one (e.g. a `health-check` capability alongside `build-run`/`test-run`) is decided concretely at this task. **Acceptance:** after a real deployment, a real post-release check runs against the real deployed target and its pass/fail result is recorded with enough detail to know what was checked and when; a failing post-release check does not fail the _task_ itself (mirroring DEVOS-064's build/test pass/fail-as-data precedent) — it is data for DEVOS-076/077 to act on.
