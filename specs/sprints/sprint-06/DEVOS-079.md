# DEVOS-079 — Full Software Change Workflow

**Dependencies:** DEVOS-072–078 (every release-stage mechanism this sprint builds), Sprint 4/5's development/validation/review workflow (DEVOS-061/067). **Scope:** "Connect all stages end-to-end" (source description) — §36 POC Implementation Sequence's final steps ("implement release readiness; implement controlled release action; implement closure and evidence; run the complete vertical slice") and §45's Reference Workflow Principle ("Development, validation, review and release are then added as subsequent vertical slices"). Wires release readiness → release approval → deployment → post-release validation → release evidence → closure into the workflow definition/version model DEVOS-013/061/067 already established, continuing whichever run-boundary pattern DEVOS-073 concluded (a new workflow version, and very likely a new, separately-gated run, mirroring the planning→development and development→rework precedents DEVOS-061/067 already set twice). **Acceptance:** a single, currently-published workflow definition (in whatever version-and-run structure the engine's existing "gates need a separate run" constraint requires) can carry a work item from an approved implementation plan through development, validation, review, release readiness, release approval, deployment, post-release validation, release evidence, and closure, with no stage requiring a hand-authored bridge outside the workflow/task/run model.
