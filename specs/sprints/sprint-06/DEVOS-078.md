# DEVOS-078 — Implement Closure Service

**Dependencies:** DEVOS-076 (release evidence), DEVOS-077 (failure handling). **Scope:** "Final outcome and linked evidence" (source description) — Stage 12 — Closure (§23): "Closure occurs only when the required workflow success criteria are satisfied. Closure should publish: final outcome; final artifacts; release evidence; review evidence; validation evidence; approval evidence; execution history; traceability; audit information. The workflow then reaches `COMPLETED`." No closure-specific database table or event is specified anywhere — reuses the existing artifact/audit/work-item mechanisms rather than introducing a new one, per this sprint's own implementation instructions. **Acceptance:** given a work item whose release cycle produced passing test evidence, a `PASS` review, a granted release approval, and successful release evidence, closure deterministically links all of that evidence together, records a final outcome, and reaches a terminal state; given any of those preconditions unmet (e.g. a failed release), closure does not silently mark the work complete — the terminal state and its evidence honestly reflect what actually happened, consistent with Workflow Principle 12 (§8) and this sprint's own failure-handling task (DEVOS-077).
