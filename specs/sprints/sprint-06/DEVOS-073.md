# DEVOS-073 — Implement Release Approval Gate

**Dependencies:** DEVOS-045/047 (approval entity + planning-approval gate precedent), DEVOS-069 (release readiness), DEVOS-072 (release policy). **Scope:** "Evidence-bound release approval" (source description) — Stage 11 — Release (§22): "The workflow must verify: ...required approval..."; Stage 6's approval rule (§16, "explicit; attributable; auditable; associated with the exact evidence/version being approved") applies equally here per ADR-SCW-002's own generalization. Reuses DEVOS-045's `Approval` entity (`approval_type: 'RELEASE'`, the same table DEVOS-045/047 already established as covering "Planning/Release/etc.") and the DEVOS-047 gate pattern (a workflow-graph marker auto-creates a PENDING approval bound to the release-readiness evidence and blocks completion until decided) — not a new approval mechanism. Whether this gate can sit inside the same run as review/release-readiness or (like planning→development and the DEVOS-067 rework loop) needs a genuinely separate run is an engine question decided concretely at this task, following the exact investigation pattern DEVOS-061/067 already used twice for an equivalent question. **Acceptance:** a release action is not reachable until a release approval bound to the correct release-readiness evidence is explicitly granted; the decision is attributable and auditable; a rejected release approval does not release and is itself traceable, mirroring DEVOS-047's reject-path precedent.
