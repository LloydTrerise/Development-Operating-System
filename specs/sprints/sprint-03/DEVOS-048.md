# DEVOS-048 — Add Uncertainty Handling

**Dependencies:** DEVOS-041 (context sufficiency determination); Sprint 2's agent result contract. **Scope:** Explicit unknown/insufficient-context states, per `specs/architecture/system-context-engineering-knowledge.md` §23: DevOS must distinguish Sufficient, Incomplete, Conflicting, Stale, and Untrusted context, and when information is insufficient, the required response is "I do not have enough information to determine this." (verbatim, also Constitution Principle 2 and Principle 13 "Fail Safely"). This extends the `uncertainty` array already defined on the Agent Result Contract (`poc-api-contracts.md` §23/§57: `{statement, severity}`) with context-sufficiency-driven detection, rather than only relying on the model to self-report uncertainty. **Acceptance:** When the context builder (DEVOS-041) determines context is incomplete or conflicting for a task, the workflow surfaces this explicitly (a queryable insufficiency signal) instead of allowing the agent to proceed and fabricate a result; conflicting authoritative information that precedence rules cannot resolve is surfaced rather than guessed at (Domain Invariant §37.5).
