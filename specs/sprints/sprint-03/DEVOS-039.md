# DEVOS-039 — Implement Knowledge Source Model

**Dependencies:** Sprint 2 foundation (DEVOS-025 agent definitions, DEVOS-011 project/membership scoping). **Scope:** Project-scoped knowledge sources — reusable information available to authorised workflows (engineering standards, architecture guidance, organisational policies, design patterns; `specs/architecture/domain-model.md` §8.1). No database table for knowledge persistence exists in `specs/database/poc-database-schema.md`, and the domain model's own vocabulary is _Knowledge Item / Knowledge Collection / Knowledge Reference_, not "KnowledgeSource" — storage/retrieval mechanism is explicitly deferred to technical architecture (`specs/architecture/system-context-engineering-knowledge.md` §39). This task's entity/table naming and shape are therefore an implementation-level assumption, flagged rather than fabricated as a spec fact, following `specs/architecture/repository-code-structure.md` §14's `packages/knowledge/src/sources/` boundary. **Acceptance:** A knowledge source is persisted, project-scoped (isolated between projects per Domain Invariant §37.7), and retrievable through a repository port; a Knowledge Reference type (per §8.3, "the relationship between a workflow, project, task, or agent and a knowledge item") is modeled and persistable now, with its actual recording wired into the context builder at DEVOS-041 once sources are genuinely selected for an execution — not fabricated here ahead of that real usage.
