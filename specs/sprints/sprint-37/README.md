# Sprint 37 — Agent Marketplace (net-new)

**Source:** `specs/DEVOS-UI-UX-REDESIGN-BACKLOG.md` §6.9 (E28 UI/UX Redesign & Full Functional Coverage, ninth sprint).
**Conversion date:** 2026-09-22
**Status:** Converted and authorized per explicit user instruction ("convert to specs and start implementation. Run the sprint through without waiting for authorisation. stop once sprint is complete", 2026-09-22, following a prior turn's own position report naming Sprint 37 as next). Depends on Sprint 23's real, already-complete agent-sharing/install primitives (`shareAgentVersion`/`listSharedAgentVersionsForOrganisation`/`installAgentVersion`, DEVOS-177/178) and Sprint 34's DEVOS-230 Agent detail view. No dependency on Sprints 35/36, though it reuses their established `Paper`/`PanelHeader` restyle convention and organisation-context patterns Sprint 29/33 established.

## Goal

Give the Agents area a real UI for the organisation-scoped agent marketplace primitive Sprint 23 built at the API layer but never wired to any client — a "Share" action on a published agent version, and a browse/install view for versions other projects in the same organisation have shared. This sprint adds zero backend routes or contract changes, per the epic's own Delivery Principle (`specs/DEVOS-UI-UX-REDESIGN-BACKLOG.md` §7/§9).

## Grounding (confirmed by direct code inspection before scoping)

- **All three routes this sprint depends on already exist, unmodified** (`apps/api/src/routes/agents.ts:104,121,135`, built in Sprint 23's E25 Agent Platform epic): `POST /agents/:agentId/versions/:version/share` (body `{ shared: boolean }`, real param names `:agentId`/`:version`, fuller than the backlog's own shorthand `:id`/`:v` — same route), `GET /organisations/:organisationId/shared-agents`, `POST /organisations/:organisationId/shared-agents/:agentVersionId/install` (body `{ targetProjectId }`, returns `{ ...Agent, version: AgentVersion }`). Confirmed via direct read.
- **Zero client wrapper exists today** — confirmed by grepping `apps/web/src/api-client.ts` for `shareAgent|sharedAgents|installAgent`: no matches.
- **`apps/web/src/features/agents/` has exactly two files today** (`AgentsPage.tsx`, `AgentDetailPage.tsx`) — no marketplace UI exists at all.
- **`Design/uploads/ui-spec.txt` §15 "Agent Catalogue"** (lines 268–286) gives only a generic field list (name/role/status/version/capabilities/knowledge access/tools/policies) — confirmed directly: no marketplace-specific interaction guidance anywhere in the document. The Share-action placement and the browse/install view's own layout are this sprint's own call, not dictated by the spec.
- **`shareAgentVersion` (`packages/application/src/agents/share-agent-version.ts`)**: only a `PUBLISHED` version may be shared (a `ValidationError` otherwise — sharing a `DRAFT` makes no sense, nothing to install yet); gated by `canPublishAgent` (project `OWNER`) — the same authority `publishAgentVersion` already requires, not a separate role; writes an `agent_version.shared`/`agent_version.unshared` audit record. **No frontend route/UI in this codebase ever checks a caller's role before rendering an action** (confirmed precedent: `AgentDetailPage.tsx`'s own `Publish` button always renders for a `DRAFT` version regardless of the caller's role, letting the backend's real `ForbiddenError` surface through the existing `ErrorAlert` pattern on rejection) — the Share/Unshare action follows this exact convention, not a new client-side permission gate.
- **`installAgentVersion` (`packages/application/src/agents/install-agent-version.ts`)**: clones the source version's `configuration` into a brand-new `Agent`/`AgentVersion` (version 1, `PUBLISHED` immediately) under a different project — a real, independent copy, never a live/linked reference (mirroring `create-project.ts`'s own `ProjectTypeAgent` → `Agent` template-clone precedent). Enforces same-organisation-only installation (ADR-SEC-005): a cross-organisation attempt returns the same `NotFoundError` every other org-scoped route in this codebase uses for a mismatch, never a distinguishable "forbidden, but it exists" response. Requires the caller to be a member of the target project.
- **`listSharedAgentVersionsForOrganisation` (`packages/application/src/agents/list-shared-agent-versions.ts`)**: requires the caller to be a member of the named organisation (`NotFoundError` otherwise, the same not-a-member-vs-not-found conflation every other org-scoped route in this codebase already uses).
- **`SharedAgentVersion` (`packages/domain/src/agents/agent-version.ts:61`) carries exactly `agentKey`, `agentName`, `sourceProjectId`** — no `sourceProjectName` field. **A real, disclosed divergence from Sprint 24/25's own `SharedKnowledgeSource` precedent** (`packages/domain/src/knowledge/knowledge-source.ts:88`), which does carry a `sourceProjectName`: the agent marketplace's browse view cannot render a source project's name directly from the API response and must resolve it client-side from the caller's own already-loaded, organisation-filtered `projects` list (`useProjectContext`), falling back to the raw `sourceProjectId` when the source project isn't in that list (e.g. the caller lost access to it since the version was shared).
- **`AgentVersion`'s frontend type (`apps/web/src/api-client.ts:670`) omits `sharedAcrossOrganisation`**, even though `toAgentVersionDto` (`apps/api/src/dto/agent.ts:29`) always returns it (`version.sharedAcrossOrganisation ?? false`) — DEVOS-244 widens the type with this already-returned-but-untyped field, mirroring DEVOS-234's own "widen with an already-returned-but-untyped field" precedent (Sprint 35, `ArtifactVersion.contentUri`/`contentHash`), zero backend change.
- **Organisation-scoping precedent**: `GovernancePage.tsx` derives a `projectOrganisationId` from the selected project's own `organisationId`, falling back to `useOrganisationContext()`'s `selectedOrganisationId`, because it is a project-scoped page that also needs organisation-level data. The Marketplace page is nav-level, not tied to a selected project, so it reads `selectedOrganisationId` directly; `useProjectContext()`'s own `projects` list is already client-side filtered to that same selected organisation (`project-context.tsx:67-73`, no organisation-scoped query parameter exists on `GET /projects`), so it is reused unmodified both to resolve a shared version's source-project name and to populate the install-target-project picker (both installation and source projects are necessarily within the same organisation as the shared version, per `installAgentVersion`'s own same-organisation enforcement above).
- **Route-ordering check**: `apps/web/src/App.tsx` already has `/agents/:id` registered as the `AgentDetailPage` route. `react-router-dom` is pinned at `7.18.2` (`apps/web/package.json`), whose route ranking always prefers a static path segment (`/agents/marketplace`) over a dynamic one (`/agents/:id`) regardless of declaration order — confirmed by React Router's own documented ranking algorithm, not assumed. No conflict.
- **No real divergence from the backlog's own framing was found** beyond the two disclosed above (no `sourceProjectName`, no frontend role-gating precedent to follow) — the three routes, their request/response shapes, and their authorisation rules all match the backlog's own summary exactly.

## In scope

- **DEVOS-244** — Agent marketplace API client: `AgentVersion` type widened with `sharedAcrossOrganisation: boolean`; new `SharedAgentVersion` type; `shareAgentVersion(agentId, version, shared)` against `POST /agents/:agentId/versions/:version/share`; `listSharedAgentVersions(organisationId)` against `GET /organisations/:organisationId/shared-agents`; `installAgentVersion(organisationId, agentVersionId, targetProjectId)` against `POST /organisations/:organisationId/shared-agents/:agentVersionId/install`.
- **DEVOS-245** — Agent marketplace UI: a Share/Unshare action on each `PUBLISHED` version row in `AgentDetailPage.tsx`'s existing Versions table (plus a "Shared" status indicator); a new `features/agents/AgentMarketplacePage.tsx` at `/agents/marketplace` (new "Agent Marketplace" nav entry in the existing Platform group, immediately after "Agents") listing every agent version shared across the caller's selected organisation, with an inline install-to-project action per row.
- **DEVOS-246** — Validation, documentation, and gap disclosure: full monorepo validation green; full real `tests/e2e` suite green; new unit tests for the 3 new wrappers; live dev-server verification.

## Out of scope

Any new backend route, use case, or domain field (no change to `shareAgentVersion`/`listSharedAgentVersionsForOrganisation`/`installAgentVersion` semantics, no `sourceProjectName` added to the DTO). Client-side role/permission gating of the Share action (the backend enforces `OWNER`-only; the UI surfaces its rejection, it does not pre-empt it). A dedicated "unshare from browse view" action (unsharing is only possible from the sharing project's own `AgentDetailPage.tsx`, matching where the Share action itself lives). Any change to `AgentsPage.tsx`'s existing list/create behaviour.
